# 微信客户管理与 OCR 智能工作台 — 项目实施计划

> **说明**：本文档用于梳理需求范围、技术边界与分阶段实施步骤。你可以直接修改、增删条目或在「确认与修改意见」列填写调整要求，确认后再按最终版推进开发。

---

## 1. 项目总览与当前基线

### 1.1 一句话目标
构建一套面向企业员工的 Windows 微信客户管理与 AI 助理系统（WinUI 3 客户端 + Go 后端）：员工通过公司分配账号登录，按员工维度隔离管理负责的客户与群组，通过受控的桌面窗口控制、UI 自动化与离线 OCR 读取界面信息并经人工核验后落库，结合知识库提供会话总结与回复建议。

### 1.2 当前已完成基线（已提交至 `main`）
- [x] **Go 后端精简骨架**（`Server/`）：Gin + 纯 Go SQLite（`modernc.org/sqlite`），已实现 `/healthz`、`/api/v1/login`、`/logout`、`/me`、`/customers`、`/customers/:id/messages`，支持按 `owner_id` 严格数据隔离及本地 `MOCK_AUTH` 联调。
- [x] **WinUI 3 非打包桌面客户端**（`Client/`）：
  - 独立强制登录门禁页（登录后进入主工作台，窗口尺寸统一固定 `1320×840`）。
  - 仿 Apifox 现代亮色工作台（顶部状态栏、左侧窄图标导航栏、底部状态栏）。
  - 微信/企业微信窗口检测、显隐与暂停标记、窗口截图与本地图片 OCR 测试。
  - 双引擎可插拔 OCR 接口（已内置 `Windows 原生 OCR`，预留 `RapidOCR PP-OCRv4` 适配位）、OCR 紫色定位框叠加、登录/主界面/掉线初判、人工核验并写入 Go 后端客户库。
  - 客户档案库展示与手动新建。

## 3. 分阶段实施步骤

### 阶段 1：业务数据底座、本地缓存与高精度 OCR（优先夯实基础）
**目标**：解决 OCR 商用准确率，补齐前后端核心数据模型，打通真实员工认证预留层。

- [ ] **1.1 接入 RapidOCR（ONNX Runtime + PP-OCRv4）**
  - 客户端引入离线 ONNX OCR 引擎实现 `RapidOcrEngine`，支持界面一键切换与 Windows OCR 对比。
  - 针对微信常见字体/深浅主题做轻量图像预处理（裁剪/放大/二值化对比测试）。
- [ ] **1.2 扩充 Go 后端数据表与接口**
  - 新增 `wechat_accounts` 表（员工与个人/企业微信账号绑定关系、在线状态、最后心跳）。
  - 扩展 `customers` 表（`local_key`、`native_id`、头像路径/URL、描述、性别、签名、地域、标签、跟进状态）。
  - 新增 `groups` 与 `group_members` 表（群档案、群内本地键、群昵称、成员关联）。
  - 新增 `audit_logs` 表（敏感操作审计：登录/登出、二维码清理、语音保存/删除、群发/消息投递）。
  - 在 `Server/internal/auth` 增加可配置的 HTTP 认证器，等待对接甲方「智美员工Bot」接口。
- [ ] **1.3 客户端本地 SQLite 缓存（对应需求 12）**
  - 引入客户端本地 SQLite 缓存联系人与群档案，支持离线毫秒级本地检索，并与 Go 后端按增量同步。

**阶段 1 验收标准**：
- RapidOCR 对微信资料页/聊天页中英数混排及微信号识别准确可用；
- 客户扩展字段、群组数据、微信账号绑定可在前后端完整读写且严格按员工隔离；
- 断网/无后端请求开销下可直接本地查询已缓存好友信息。

---

### 阶段 2：微信状态巡检、二维码安全登录与会话识别
**目标**：跑通微信生命周期监控（登录 → 在线绑定 → 窗口显隐 → 掉线熔断 → 退出登录）。

- [ ] **2.1 后台状态巡检与任务调度器（需求 2、18、19）**
  - 建立客户端任务队列与状态机（`Idle / Running / PausedByHidden / StoppedByDisconnect`）。
  - 定时结合进程状态、窗口句柄和 OCR 检查掉线弹窗或窗口最小化，触发自动熔断停止后续键鼠任务。
  - 窗口恢复显示后自动复核当前绑定账号，确认一致再允许恢复任务。
- [ ] **2.2 刷新并获取登录二维码（需求 3）**
  - 定位微信登录页二维码区域，支持触发刷新并截取本地临时图展示在工作台。
  - 严格执行安全规则：不上传服务端、不长期保存，扫码核验完成后立即物理删除并写审计日志。
- [ ] **2.3 当前聊天窗口识别与资料页提取（需求 4、17）**
  - 读取当前会话标题、备注、微信号候选值，关联本地对象键，支持截图裁剪保存客户头像。
- [ ] **2.4 受控退出登录（需求 11）**
  - 人工二次确认后执行微信退出流程，复核回到登录页并停止任务，保留历史客户与聊天数据。

**阶段 2 验收标准**：
- 微信掉线或隐藏时，客户端能自动识别并阻止任何自动化任务执行；
- 二维码临时文件在登录完成后自动清理且有日志可查；
- 切换不同微信窗口/会话时，工作台可准确联动当前客户信息。

---

### 阶段 3：受控键鼠执行、消息收发与批量采集
**目标**：打通安全可控的桌面操作闭环（所有高风险动作均遵循「定位核对 → 人工确认 → 执行 → 截图复核」）。

- [ ] **3.1 Windows UI Automation + 受控键鼠引擎**
  - 封装统一窗口激活、目标搜索、安全输入/剪贴板粘贴、滚轮滚动、区域截图与结果核验基础组件。
  - 兼容微信 3.x / 4.x 与企业微信的窗口结构差异（采用策略适配模式，便于随微信更新调整）。
- [ ] **3.2 受控消息发送与好友通过（需求 7、8、9、10）**
  - 文本消息发送：定位并核对会话 → 输入文本 → 人工确认发送 → 截图核验气泡。
  - 图片消息发送：选择本地图片 → 预览核对 → 发送并校验状态。
  - 群聊 `@` 成员：输入 `@` → 识别候选列表（重名弹窗人工核对）→ 确认发送并校验 `@` 状态。
  - 同意好友请求：识别新朋友列表 → 人工逐条勾选通过 → 核验新增联系人入库。
- [ ] **3.3 通讯录与群成员断点续扫（需求 5、6、13、14）**
  - 实现通讯录与群成员滚轮遍历 + 资料页采集，持久化扫描进度支持中断后续扫与速率限制。
  - 支持在线补全单个联系人的扩展资料（控频、容错）。
- [ ] **3.4 原图下载与授权语音归档（需求 15、16）**
  - 支持原图查看与另存到本地指定目录，校验文件落盘路径。
  - 语音保存采用可开关配置，限定授权目录、访问权限与保留期限，提供一键删除与审计记录。

**阶段 3 验收标准**：
- 文本、图片、群 `@`、好友通过全流程人工可控、无误发、有截图核验结果；
- 通讯录/群成员扫描中途关闭或微信掉线后，重启可从断点继续；
- 所有敏感媒体操作具备清晰目录边界和审计记录。

---

### 阶段 4：知识库与 AI 助理工作台
**目标**：结合客户画像、近期聊天记录和公司知识库，辅助员工高效回复与跟进。

- [ ] **4.1 后端知识库与 AI 服务**
  - 新增知识库文档/FAQ 管理表与检索接口（支持关键词/向量检索）。
  - 对接大模型接口，提供「会话总结」和「回复草稿生成」API，并对高风险场景（投诉、退款、价格承诺等）返回风险标注。
- [ ] **4.2 客户端 AI 助理侧边栏**
  - 在工作台右侧集成 AI 面板：一键总结当前客户近期聊天、生成 1~3 条推荐回复草稿。
  - 员工编辑审核后可一键送入阶段 3 的受控发送流程；高风险问题强制提示转人工处理。
- [ ] **4.3 打包与交付准备**
  - 编写安装部署脚本（Go 服务端配置模板 + WinUI 3 自包含安装包 + RapidOCR 模型打包）。
  - 输出交付部署文档与操作手册。
